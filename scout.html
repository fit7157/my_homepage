Project overview

Human following without forcing RGB and depth into one heavy pipeline.

The key idea was to separate visual tracking and distance processing. The RGB stream handles person tracking, while the depth stream is processed independently for distance estimation. This reduces unnecessary processing and improves the responsiveness of the human-following system.

Processing architecture

One camera.
Two processing paths.

RGB and depth are not forced into one synchronized processing callback. Each stream has its own role and can be processed at an appropriate rate.

RGB PIPELINE

Visual tracking stays focused on direction.

The RGB frame is used to detect the person and calculate the horizontal difference between the center of the person and the center of the camera frame. This tracking error is used to calculate angular velocity.

RGB frame → Human detection → Center error → Angular velocity
DEPTH PIPELINE

Distance is calculated independently.

Depth frames are processed separately. Depth values around the detected target position are used to estimate the distance between Scout Mini and the person.

Depth frame → Target ROI → Distance
WHY SEPARATE THEM?

Not every sensing task needs to run at the same rate.

Person direction can change quickly, so RGB tracking should remain responsive. Distance generally changes more gradually, allowing depth processing to run independently. Separating the RGB and depth processing paths reduces unnecessary computation and improves control responsiveness.

Core implementation

RGB for steering.
Depth for following distance.

RGB STREAM

Where is the person?

The center position of the detected person is compared with the center of the camera frame. If the person moves left or right, Scout Mini rotates toward the target. A dead zone around the center prevents unnecessary small steering corrections.

Output → angular velocity
DEPTH STREAM

How far away is the person?

Depth values near the detected person are sampled to estimate target distance. This distance can be used to increase forward speed when the person is far away and reduce the speed as Scout Mini approaches the desired following distance.

Output → linear velocity

Control flow

Detect. Measure. Publish. Move.

01

Receive RGB and depth streams.

The RGB-D camera publishes visual information and distance information as separate ROS2 image streams.

02

Track the person in RGB.

The target's center is estimated from the RGB image and compared with the camera center to calculate steering error.

03

Estimate target distance from depth.

Depth values near the tracked target provide the distance required for forward-motion control.

04

Publish /cmd_vel and send the command through CAN.

The human-following node publishes linear and angular velocity through /cmd_vel. The Scout Mini ROS2 driver subscribes to this topic and sends the motion command to the robot through CAN communication.

Separate perception.
Connected control.

By processing RGB and depth independently, the system avoids forcing every perception task into one synchronized processing cycle. ROS2 connects perception and control through topics, while CAN communication delivers the final velocity commands to Scout Mini.
